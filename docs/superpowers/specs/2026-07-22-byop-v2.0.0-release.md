# v2.0.0 release notes — subcommands + persistent profiles

## What's new

### Persistent profiles

`byop` now remembers your provider as a **profile** stored at
`~/.config/byop/profiles/<name>.toml` (XDG-aware via `platformdirs`). The
global `~/.config/byop/config.toml` points at the *active* profile via
`active_profile = "default"`.

API keys are **never** stored in the profile — the `api_key_ref` field
points at where the secret lives (`"keychain"` or `"env:VAR_NAME"`).

### Subcommands

| Command | Purpose |
| --- | --- |
| `byop` | Status dashboard (or first-run wizard when no profile exists). |
| `byop status` | Read-only dashboard. |
| `byop apply [flags]` | Sync the active profile to selected targets. |
| `byop doctor` | Drift detection. |
| `byop profile list` | Show saved profiles (active first). |
| `byop profile use <name>` | Switch active profile. |
| `byop profile new` | Create a new profile (interactive). |
| `byop profile edit` | Re-run the wizard pre-filled with the active profile. |
| `byop profile export` | Print active profile as JSON. |
| `byop profile delete <name>` | Delete a saved profile. |
| `byop export-config` | Dump target settings as JSON. |

The legacy top-level-flag UX (`byop --provider P --api-url ...`) still works
— it's automatically routed to `apply`. So existing scripts and CI pipelines
don't need to change.

### Bare `byop` is now a dashboard

When a profile exists, bare `byop` shows the status dashboard instead of
re-running the wizard. On the first run (no profile yet), it drops into the
wizard as before.

### First-run flow

1. Bare `byop` → wizard collects provider info
2. Wizard result is saved as the `default` profile
3. Secret is written to the macOS keychain
4. CLI prompts to install/configure each target

### Subsequent runs

1. Bare `byop` → status dashboard
2. Wizard skips fields already in the profile (just press Enter to keep)
3. `byop apply` syncs the active profile to all targets in one keystroke

## Why this is better

- **One keystroke to re-apply.** `byop apply` (or just `byop` on the
  dashboard) uses the saved profile. No re-entering the API key, no re-typing
  the model list, no re-answering capability questions.
- **Multiple profiles.** Users who flip between work/personal providers can
  keep both around: `byop profile new work`, `byop profile new personal`,
  `byop profile use personal` to switch.
- **Drift detection.** `byop doctor` compares the active profile against
  each target's actual settings and reports mismatches.
- **State inspection.** `byop export-config` and `byop profile export` make
  it easy to see what's actually configured without opening settings.json.

## Design choices

- **TOML over JSON** for the profile store. Stdlib `tomllib` for reads,
  `tomli-w` for writes. Matches `gh`/`cargo`/`kubectl` conventions and is
  user-editable.
- **XDG-compliant** via `platformdirs`. Honors `XDG_CONFIG_HOME` and
  `BYOP_CONFIG_DIR` for tests.
- **Two-file split** (settings + profiles) mirrors `gh`'s `config.yml` +
  `hosts.yml` pattern. Makes profile switching atomic.
- **No TUI / Textual.** Out of scope for ~600 LOC. Rich + simple prompts is
  the right minimum.

## New dependencies

- `platformdirs >= 4.0` (MIT, stdlib-friendly)
- `tomli-w >= 1.0` (write-side TOML; reads use stdlib `tomllib`)
